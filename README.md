# 维修复验与部件追踪

本项目用于整理社区服务运营数据。`fixtures/` 保存本地合成源记录，各表字段和业务时序约定见 `DATA.md`。没有线上服务或真实个人信息。

## 质量台账

`ledger/` 用报修、设备服役关系、实际通行机会和检修回执安排复验，不以"关单之后几天没有报修"认定修好：

```sh
python3 -m ledger            # 文本台账（九节）
python3 -m ledger --json     # 结构化输出
python3 -m ledger --fixtures fixtures --as-of 16
```

台账内容：

- **维修观察台账**：每次维修的风险观察窗（关单次日起算、同门再修截断）、实际开放观察日（绕行/关机/缺观测分列）、漏读日上下界、复发计数与率的可支持范围（漏报区间不单作零）。
- **拆解**：按维修方式、施工队、设备族；未定归属的通报只进"未定"桶，不既认作批次故障又认作施工故障；共享控制器一次停用引起的多条通报不当作独立复发证据。
- **部件服役与故障史**：部件故障史随件走，点位故障史留点位，成套换件沿用件保留历史。
- **复验安排评估**：每个选项能区分哪些开放假设、不能区分哪些；替代门需符合该院通行要求且有本场通行回执；任何院在有人通行时不得同时失掉所有符合要求的门；待确认备件移用时另一位置重核，依赖同一部件的验证不互为独立证据。
- **方案比较**：各安排可消除的疑问、仍受限制的时段、受影响的使用方。
- **记录更正的影响**：已完成的施工不可撤销重演仅注记；未执行的复验安排按更正后事实重核；已发布的质量比较中失去可比观察的项重新标出。
- **放行／暂停决定**：暴露不足、仍有复发证据、没有可用的替代门等原因分列，不并成一个故障率。
